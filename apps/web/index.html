How it plays

One ticket, four moves

  1. 1

    Pin

    Your open GitHub issues become cards on the office board, coloured by label.

  2. 2

    Give

    Drop a card on an agent. It walks over, takes it, opens a branch and gets to work.

  3. 3

    Approve

    Every edit, command and push raises a “!”. You read the full command, then decide.

  4. 4

    Merge

    The pull request lands on your desk with its checks. Merging is always your move.

The board is your GitHub

Issues in, pull requests out

Noburi reads your repository through your own gh login. Each agent works on its own branch in a private clone, and what it ships comes back as a real pull request that closes the issue.

Nothing behind your back

You see every command before it runs

Reading files is free. Anything else waits for you, shown whole, never summarised. Refuse once and the agent stops and tells you what it was about to do.

Your engines, your accounts

Agents on the CLI you already use

Agents run on the Claude Code you installed, with your own subscription. Codex and Gemini CLI are planned. Noburi stores no token.

House rules

  • No fake work

    An agent shown typing is really running a tool.
  • Only you merge

    Agents open pull requests. They never merge.
  • Local first

    Missions and history stay in SQLite on your machine.
  • Your name on commits

    No AI trailers in commits or pull requests.
